## 1. Processos de Ciclo de Vida do Software (ISO/IEC 12207)
A norma ISO/IEC 12207 estabelece uma estrutura comum para os processos de ciclo de vida de software. O projeto percorre os processos primários:

1. **Aquisição e elicitação:** mapeamento das carências energéticas e dos dados necessários junto às fontes oficiais (IBGE, ANEEL, INPE) — ver [requisitos](../requisitos/especificacao_requisitos.md) e [stakeholders](../stakeholders/analise_stakeholders.md).
2. **Fornecimento:** definição da arquitetura técnica e especificação formal dos requisitos.
3. **Desenvolvimento:**
   - análise de requisitos (RF e RNF com critério de aceitação);
   - projeto de arquitetura (camadas rotas → controllers → services → models);
   - projeto detalhado (diagramas UML e modelo relacional);
   - codificação e testes unitários/de integração (Jest, Supertest);
   - testes de sistema no navegador (Playwright) e verificação matemática do TOPSIS.
4. **Operação e manutenção:** contêineres Docker, migrations versionadas, documentação OpenAPI/Swagger e integração contínua.

A rastreabilidade requisito → caso de uso → código → teste está na [matriz de rastreabilidade](../requisitos/especificacao_requisitos.md#4-matriz-de-rastreabilidade).

## 3. Medidas de Segurança Adotadas

- Senhas armazenadas apenas como hash bcrypt (custo 10); a resposta do login não diferencia usuário inexistente de senha errada.
- Token JWT com validade de 8 horas; a cada requisição o usuário e o perfil são relidos do banco (conta excluída ou rebaixada perde o acesso na hora).
- O segredo do JWT nunca fica no código: vem da variável `JWT_SECRET` ou é gerado aleatoriamente na primeira execução.
- Limite de tentativas de login por IP (20 a cada 15 minutos).
- Controle de acesso por perfil em cada rota; não existe cadastro público de usuários.
- Dados de entrada validados no servidor; nomes vindos do banco são exibidos como texto (sem interpretação de HTML) na interface e protegidos contra injeção de fórmulas no CSV.
- CORS restrito às origens configuradas.
